# GitHub Issues

GitHub's issue endpoints are appropriate for triage, bug intake, work tracking, and factual progress logging.

Use issues for:

- bug reports
- implementation tasks
- follow-up tasks from code review
- operational incidents tied to a repository

Issue operating rules:

- Search existing issues before creating a new one.
- Reuse labels and assignees consistently with repository conventions.
- Keep issue titles factual and searchable.
- Use comments for evidence, investigation notes, and next actions.
- Do not create noisy duplicate issues when a pull request or issue already tracks the work.
