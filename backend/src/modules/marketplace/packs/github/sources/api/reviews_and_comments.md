# GitHub Reviews and Comments

Reviews and comments are collaborative surfaces, but they still affect workflow state and signal intent to humans.

Use comments for:

- factual status updates
- clarifying questions
- review observations tied to code or behavior

Use review endpoints for:

- structured review submissions
- review comments on changed lines
- reviewer requests or reviewer state inspection

Rules:

- Keep comments evidence-based.
- Do not claim a change was tested unless evidence exists.
- Do not request reviewers automatically unless the approval policy permits it.
- Treat reviewer assignment as an approval-gated workflow action.
